#### Database

- Use SQLite with SQLAlchemy ORM and proper relationships.
- Required tables: Roles, Users, Parking Owners, Parking Lots, Parking Staff, Customers, Vehicles, Parking Floors, Parking Slots, Reservations, Parking Sessions, Payments.

#### User Roles & Permissions (High-level)

- **System Admin**: manage owners, users, roles, view reports and all resources.
- **Parking Owner**: manage own lots, staff, floors, slots, view reservations/sessions/revenue.
- **Parking Staff**: handle entry/exit, confirm reservations, update slot status, manage sessions.
- **Customer**: register, manage profile & vehicles, search lots, reserve slots, make payments.

#### Authentication

- JWT-based authentication with refresh tokens.
- Endpoints: register, login, refresh, logout, change password, update profile, get current user.
- Passwords must be hashed using `passlib`.

#### Business Rules & Modules

- User hierarchy: `created_by` stores creator user id (Admin creates Owners; Owners create Staff).
- Parking Lot: CRUD, search, filter by type/owner, geographic fields (lat/lng), Google Map URL.
- Parking Floor: CRUD per lot.
- Parking Slot: CRUD, status (`AVAILABLE`, `RESERVED`, `OCCUPIED`), update status endpoints.
- Reservation: statuses (`PENDING`, `CONFIRMED`, `CANCELLED`, `COMPLETED`); only `AVAILABLE` slots can be reserved.
- Parking Session: statuses (`ACTIVE`, `FINISHED`), start/finish session, calculate duration & fee; slot status changes accordingly.
- Payments: statuses (`PENDING`, `PAID`, `REFUNDED`), support payment methods (KBZPay, WavePay, AYA Pay, UAB Pay).

#### Search, Pagination, Filtering, Sorting

- Search by lot name, address, company name, vehicle plate number, customer name.
- Pagination via `page` & `limit` query params.
- Sorting via `sort_by` & `order`.
- Filtering by type, status, owner, floor, reservation status, payment status.

#### API Response Format (examples)

Success:
```json
{
	"success": true,
	"message": "Parking lot created successfully.",
	"data": {},
	"meta": {"page":1,"limit":10,"total":100,"total_pages":10}
}
```

Error:
```json
{
	"success": false,
	"message": "Validation failed.",
	"errors": [{"field":"email","message":"Email already exists."}]
}
```

Unauthorized:
```json
{ "success": false, "message": "Unauthorized." }
```

Not Found:
```json
{ "success": false, "message": "Resource not found." }
```

#### API Standards & Best Practices

- Use HTTP status codes correctly and return JSON.
- Use async endpoints where appropriate and validate inputs with Pydantic v2.
- Implement RBAC and dependency injection for security.
- Log key events and use DB transactions for critical operations.
- Keep business logic in services and DB logic in repositories.
- Autogenerate OpenAPI docs (Swagger & ReDoc).
